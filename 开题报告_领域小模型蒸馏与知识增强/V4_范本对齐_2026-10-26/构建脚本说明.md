# V4 构建与检查说明

## 当前入口与格式

正文为开题报告_正文_V4.md，正式交付Word为开题报告_V4.docx，技术路线使用同目录技术路线.png，方向说明为开题报告_V4_方向简介.html。保留原有三章模板结构：背景与意义、文献综述、研究内容/方案/时间。当前40条参考文献、公式（1）至（7），以正文和V4_文献逐条核验.json为准，不沿用旧版26条或63条计数。

使用现有build_report.py的build接口，明确指定输入、输出与图像，不依赖默认文件名：

    from pathlib import Path
    import build_report as br
    br.build(Path('开题报告_正文_V4.md'), Path('开题报告_V4.docx'),
             fig_path=Path('技术路线.png'), static_toc=False,
             fig_caption='图 3-1　技术路线图')

Python环境为/home/yin/study/KaiTi/.venv-docx/bin/python，包含python-docx。默认覆盖保护适用于命令行；库调用前应核对目标文件。技术路线通过dot -Tpng生成，新图必须在Word构建前完成。

## 本轮额外排版

沿用原有A4尺寸、上下2.54 cm及左右3.17 cm页边距，正文12 pt宋体、1.3倍行距及原有标题字号。构建后对交付Word将模板学校文字与填报日期显式改为留空字段，全部六项个人字段也留空；长题目分两行。表头设置重复、表格行不拆分；七处公式用10.5 pt可读Unicode文本，无首行缩进。

本轮未改排版程序，不声称它原生支持LaTeX或OMML。若直接重建，会重新出现程序内置的学校文字，因此重建交付时须重新核对学校与个人字段；不能仅因COVER_FIELDS为空就认定所有封面信息均已留空。

## 目录与临时PDF

正式Word为TOC域模式，打开后更新目录域可得到页码。临时验收使用static_toc=True生成另一份Word并以LibreOffice转PDF，均保存在/tmp/kaiti-v4-engineering-preview，不加入仓库，不覆盖正式Word。该预览为17页，静态目录无页码；正式Word的最终分页可能随Word字体与目录更新变化。

## 针对性验收

- 正文引用集合与连续40条书目双向对应，逐条题名匹配本轮元数据，编号闭合不替代来源核查。
- Word文献书签实际包住[n]编号，REF域数量与引用相关，不能只查书签存在。
- 正文、公式与表格在临时PDF完整出现；跨列表格需兼用pdftotext -raw阅读顺序检查，避免layout文本交错误报。
- 嵌入图片字节与当前PNG的SHA-256一致，图题与正文对应，另行目视检查中文渲染。
- HTML通过标签、锚点与本地文件链接检查，Chrome直接打开file URL检查桌面和窄屏；不启动新的DSH或Web服务。
- 封面学校、指导教师、单位、姓名、学号、专业、入学时间、填报日期均留空；计划使用相对月份。

本轮未改构建脚本、未运行整套代码测试。文稿与排版检查仅证明交付一致性，不证明两项算法已经实现或取得实验效果。
