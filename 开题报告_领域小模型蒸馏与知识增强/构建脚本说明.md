# 构建脚本说明

## 用途

`build_report.py` 把 `开题报告_正文.md` 渲染成符合北京科技大学开题报告格式的 Word 文档。

格式基准取自同目录的两份范本：
- `开题报告-唐宁俊V3.docx`
- `开题报告-李壮壮V1.3.docx`

## 用法

```bash
# 1. 生成 Word（目录用 TOC 域，Word 打开后自动提示更新）
../.venv-docx/bin/python build_report.py

# 2. 生成带静态目录的版本（用于转 PDF，因为 LibreOffice 不计算域）
../.venv-docx/bin/python build_report.py --static-toc

# 3. 指定输入输出
../.venv-docx/bin/python build_report.py 某正文.md 某输出.docx
```

默认输出 `开题报告_格式版.docx`。

## Markdown 约定

脚本按以下规则解析正文：

| Markdown | 渲染为 |
|---|---|
| `# 标题` | 文档题目（只用于封面，不输出到正文） |
| `## 一级` | Heading 1（章） |
| `### 二级` | Heading 2（节） |
| `#### 三级` | Heading 3（小节） |
| `**粗体**` | 加粗 |
| `[1]` `[2]` | **上标**（学术引用惯例） |
| `{{FIG41}}` 或 `{{FIG31}}` | 插入技术路线图 + 图题 |
| `\| a \| b \|` 表格 | 转成 Word 表格 |
| `## 参考文献` | 其后每行 `[n] ...` 解析为参考文献条目 |

## 目录的两种模式

**TOC 域模式（默认）**
- 插入 Word 目录域，`updateFields=true`
- Word 打开时会提示「此文档包含的域可能引用其他文件，是否更新？」
- 选「是」即生成带页码的真实目录
- 优点：页码自动、可点击跳转

**静态目录模式（`--static-toc`）**
- 直接写入标题文字，不含页码
- 用于 LibreOffice 转 PDF（它不计算域）
- 优点：PDF 里能看到目录

**建议流程**：Word 版用默认模式（在 Word 里更新域），PDF 版用 `--static-toc` 生成后转换。

## 注意事项

**1. 个人信息全部留空。** 封面六项信息与日期均为下划线占位，需手填。

**2. 章节结构需与范本对齐。** 范本是三章结构；当前正文有六章（多了「拟创新点」「可行性」独立成章）。脚本按 Markdown 标题原样输出，不会自动合并章节。若要严格对齐范本，需先调整 md 的章号。

**3. 图题编号写死在脚本里**（「图 4-1　技术路线图」）。若正文章节调整，需同步修改脚本中 `render_blocks` 里的图题文字。

**4. 数学公式原样输出。** `$...$` 不做渲染，会以源码形式出现在 Word 里。当前正文有意保留了少量公式源码，如需正式排版应改用 Word 公式编辑器或转成图片。

**5. 依赖版本。** 使用 `/home/yin/study/KaiTi/.venv-docx/bin/python`（python-docx 1.2.0）。系统 python 若无 python-docx 会报错。
